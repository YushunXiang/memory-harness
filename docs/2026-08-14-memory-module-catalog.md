# E-MAC Memory Module Catalog

日期：2026-08-14

## 选择原则

只加入能改变至少一个独立架构维度、且能在 RMBench 上形成明确消融的模块。论文中的完整模型不会被包装成一个名字；而是拆成 `encode / write / store / retrieve / utilize / lifecycle` operator。需要学习的 operator 必须携带自己的 checkpoint 与训练 recipe，不能伪装成无需训练的配置开关。

### 当前可执行边界

当前 registry 的 executor path 是一个已打通端到端的 `dense_tokens[M,D] + mask[M]` 家族：Mem-0 anchor/sliding、无训练 write/store/retrieve 算子和 token utilizer 可在同一 runtime 中组合；planner-side key history 通过独立 typed facade 接入。动作序列、wrench、fast weights、MoE routing profile、point cloud 和 SE(3) pose 是不同 payload family，目前只是经论文支持的候选，不在 executable registry 中。只有首个该类候选通过当前 Gate 并进入实现时，才为它增加最小 typed payload contract 和 encoder→retriever→utilizer 兼容性 preflight；runner、benchmark 和 audit event 语义保持不变。这样 Agent 搜索的是真正可运行的组合，而不是把异构 payload 硬塞进 `metadata` 或在 rollout 时才发现不兼容。

## 不加入的重复项

- 不单独实现 RNN/LSTM/GRU catalog：HAMLET 的同预算消融中 Transformer consolidation 更好；这些只是同一 consolidation 维度的弱替代。
- 不把 Auto-Robotist 登记成 robot-policy memory operator：它把 morphology-search trial 蒸馏为包含正负规则与支撑设计的 skill library，新增价值属于 Research Agent 自身的经验管理。后续只复用 `evaluated candidate → add/diagnose/merge lesson → retrieve lesson` 的搜索循环，并将 research-memory 与部署时 observation memory 严格分库。
- 不把“直接拼接历史 token”作为新方法：HAMLET 报告 Moment Concat 几乎等于无记忆；它只保留为负对照。
- 不把 [RoboHarness](https://arxiv.org/abs/2607.18060) 的 Memory Bridge 加成当前单-policy memory operator：其 linked multimodal trajectory、semantic/visual retrieval、spatial state scoring 与 handoff guidance 分别和现有跨 episode trajectory bank、OpenSPM-style spatial transfer、completed-phase handoff 重叠；真正的新假设是**异构 policy 的入分布交接**，应在进入多 policy architecture evolution 后作为系统级 program，而不是复制一套 executor memory。
- 不新增另一个手工 keyframe store：它与 Mem-0 key/subtask history 重复。后续有新价值时应体现为新的 write/retrieve rule，而不是复制 store。
- 暂不把跨 episode latent retrieval 与 episode 内 memory 混入同一排行榜：它属于持续部署假设和额外在线数据预算。`verified_success_ring` 已提供最小可执行 lifecycle lower bound，但必须使用 ordered episodes、单独报告 bank warm-up，并与 empty/frozen-bank 配对。
- 不把 Retrieve-then-Steer 再登记成一套 trajectory store：它与 OptimusVLA GPM 共享 action-prior payload、progress alignment 和 flow-sampler utilization。当前只实现其不重复的 `outcome-verified online write` 生命周期；consistency filter 与 confidence-adaptive guidance 继续作为 action-prior family 的独立 operator，不能用 latent FIFO 冒充。
- 不把 HyMeS 整体包装成一个 memory plugin：它同时改变 task plan、progress verifier 和 flow-matching action generation，无法归因到单个 memory operator，也破坏当前 fixed-memory 的同 utilization 比较。其可复用部分应逐层拆成 `symbolic_task_state` 与 `multimodal_progress_verifier`；task-specific constraint reward 保留为外部 steering baseline。
- 不把 ALMA 登记成 robot-policy memory operator：它搜索 Research Agent 生成的整段 text-memory Python，而不是新的 VLA payload/store。只复用其非贪心 archive sampling、成功/失败 trace reflection 与 generate-validate-debug 搜索循环，并用 content identity、typed capability、sandbox、locked-task 和 matched-budget 约束替换原版宽松运行边界。
- 不把 MemEvolve 登记成 robot-policy memory operator：它搜索 text-agent provider code，四段接口还把 encode/store 与 lifecycle 混在 `take_in_memory` 中。只复用 budget-aware Pareto survivor 与 frozen cross-task transfer；其 trajectory diagnosis、代码生成和 debug 与 ALMA/KDLoop 去重合并，不能再复制一套搜索循环。
- 不把 EvoMem 登记成 robot-policy memory operator：只复用其 lineage-evidence promotion writer，连接已规划的 Auto-Robotist research-memory record；公开附件缺实现，不能把本地透明阈值称为论文复现，也不能把观察性 lineage delta 写成单机制归因。
- 不把 AgentCanvas/KDLoop 登记成 robot-policy memory operator：它是 Research Agent 的 typed executor substrate 与搜索策略。直接复用其 type preflight、atomic run、axis coverage、post-selection rerun 和 leak rejection 范式，并作为同预算 search baseline；不把搜索基础设施与部署时 memory 模块混为一个候选。
- 不把 [HoloAgent-0](https://arxiv.org/abs/2606.23565) 或 [ABot-AgentOS](https://arxiv.org/abs/2607.10350) 整体加入 executor registry：两者都是导航、工具、技能与持久多模态/空间图 memory 的 AgentOS 级系统，没有在同一 VLA 上隔离出不同于 eMEM、structured object/scene graph 和 3D spatial map 的新 operator。它们可作为未来跨 episode persistent-memory 系统参照，但现在新增总开关会重复计数并破坏 RMBench 的 fixed-backbone 消融。
- 不把 Notes-to-Self 另建成与 MEM 重复的 language store：新增价值在固定 `Grounding/Plan/Act` schema 和 learned `<done>` write trigger，应作为同一 language branch 的 representation/write 两个选项消融。
- 不把 [S²-VLA](https://arxiv.org/html/2606.27872) 另建成新的 memory family：其 belief-state guided mid-layer gate 与 TFP 的 recurrent belief + decoder modulation 属于同一 `state update × learned utilization` 轴；论文最优 Gate@12 相对无 gate 仅为 `96.4% vs 95.0%`，而 all-layer gate 降到 `94.4%`。后续只把“单个中层注入位置”登记为 TFP/recurrent-state utilizer 的位置消融，不复制整套 architecture。
- 不把 [CodeGraphVLP](https://arxiv.org/abs/2604.22238) 整体加入 executor registry：persistent semantic graph 与已登记 concept-centric object/scene/relation payload 重叠，code planner 与 clutter-suppression 又同时改变 planner 和 observation。若后期进入 structured memory，只复用其 progress-check 与 object-filtered utilization 作为系统对照，不新增 `codegraph_memory=true`。
- 不把 OnEvoMemory 称为 architecture evolution：它通过 rollout 更新固定三-bank 系统中的 value estimator、writer 和 injection 参数，没有让 Agent 生成、替换或组合 memory operator。E-MAC 必须将它作为 learned-controller 强基线，并另外证明 typed program search 相对该固定结构的价值。论文源码审计还表明，`N_s=4 / bank=2048 / semantic-4+recent-2 / threshold / merge / eviction / online loss` 等常被当作实现细节的内容全部位于未渲染的 TeX 注释块；在官方 release 出现前只能把正文的算子关系作为 paper contract，不能宣称忠实超参数复现。
- 不把 OptimusVLA 的 LCM 再登记成独立“action-history memory”：官方 release 实际缓存完整上一条**预测** action chunk，并只在 GPM prior 存在时把 cross-attention+Mamba bias 加到 flow initialization；这与已登记的 ChainVLA Motion Tail 高度重叠，也没有公开独立训练入口。当前只纳入不重复的 GPM/action-prior family；若以后比较 LCM，必须作为 `previous predicted chunk × retrieved prior` utilizer 消融，不能宣称是已执行 action history。
- 不把 BehaviorVLA 再登记成第二套跨 episode action-prior architecture：其独立价值是完整轨迹学习出的 behavior prototype representation 与三阶段训练 recipe；top-k bank retrieval、progress-conditioned action prior 和 decoder conditioning 已属于 OptimusVLA/GPM family。官方 release 的在线 local token 是 `current image + previous executed action` 的 stateless encode，并非新的 recurrent store。
- 不把 Harness VLA 整体加入 memory operator catalog：它利用 task/global execution traces学习 frozen VLA 与 analytic primitive 的适用范围，同时改变 planner、primitive vocabulary 和执行栈；这可作为 task-specific agentic-system 参照，但不满足当前同 π0.5 utilization 的可插拔模块比较边界。
- 不把 [HiMe](https://arxiv.org/abs/2607.03449v1) 整体包装成新 memory operator：其 Executor/Sentry/Planner 多速率系统可由现有 `recent window → structured key memory → revisable lifecycle → subtask-conditioned executor` 组合表达，因此不新增重复 payload family。官方源码 commit `261766e…` 的 CRUD/save-resume/FIFO 最小 smoke 通过，但仓库无顶层 license、无 tests/checkpoint/data；源码 FIFO 容量为 20、论文为 8，exact-tag 分支请求 `top_k=2` 实际返回 7 条，默认 full store 又无界。故只保留不重复的 `subtask_completion_sentry_planner_trigger` 与 `planner_generated_multimodal_crud_lifecycle` 两个 source-level 轴；后者进入 harness 前必须增加 fail-closed policy、namespace、record version/evidence、原子事务、tombstone、bounded retrieval 和 audit log。未来按 matched Planner-call 预算分别比较 trigger 与 CRUD，不能用一个 `hime=true` 重复计数已有模块；完整审计见 [`artifacts/2026-08-16-hime-source-audit.json`](../artifacts/2026-08-16-hime-source-audit.json)。
- 不把 [VerMem](https://arxiv.org/abs/2608.03137v1) 的七种操作再登记为一套 payload：LTM Add/Update/soft-Delete 和 STM Retrieve/Filter/SelectEpisode/Summarize 都可由现有 typed store、retrieve 与 lifecycle 表达。真正新增的是 `unified_ltm_stm_atomic_memory_operation_policy`、versioned soft-delete transaction、realized-transition local verifier、terminal-consistency global verifier、operation-normalized hierarchical credit 与 `LTM→STM→joint` curriculum。论文 Qwen2.5-7B 平均由 no-verifier `41.76%` 提至 full `48.01%`，但官方 commit `4782751…` 只定义 schema、没有状态存储或 operation executor；发布 verifier 与论文 DeepSeek-V3.2 不符，reward loader 还使 local/global/credit 全部为零，且无 checkpoint/data/run。因此只冻结 [`artifacts/2026-08-16-vermem-source-audit.json`](../artifacts/2026-08-16-vermem-source-audit.json)，不增加第 18 个 source family 或 executable stub。后续以 harness-native typed transaction 实现，并把 VerMem 作为固定模块 Gate 1 后的 operation-controller 训练基线，而不是 architecture search 的替代品。
- 不把 [From Signals to Structure](https://arxiv.org/abs/2607.00233v1) 的五个 condition 登记成新 memory：所有条件都有相同 rolling-20，额外的 shared convention board、150-word private scratchpad、10-slot codebook 和 codebook+meta 分别由现有 shared KV、recursive language summary 与 bounded structured slots 覆盖。其价值是评测约束：cap=25 时 scratchpad/memory-only late accuracy 为 `0.867/0.747`，cap=64 为 `0.760/0.580`；memory-only 在 cap=64 把 history window `20→40` 仍停在 `0.52`，说明 architecture 与 capacity/history 有交互。codebook+meta 又低于 codebook，qualitative trace 暴露 stale/conflict 和 revision drift。故只保留 `post_gate_architecture_capacity_history_sensitivity_factorial`、组合 conflict/staleness/revision trace 和 utility/structure 分报，完整审计见 [`artifacts/2026-08-16-signals-to-structure-paper-release-audit.json`](../artifacts/2026-08-16-signals-to-structure-paper-release-audit.json)。该工作只用单一 closed model 的 symbolic game，多数条件单 seed且无 release，不改变 17-family catalog、21-candidate suite 或活动 RMBench gate。
- 不把 HELM 整体包装成 memory plugin：其 CLIP keyframe EMM 与现有 event-write + semantic retrieval 重复，主要新增价值是 learned failure verifier 和 rollback/replan controller；后两者属于 action verification/recovery，不应冒充新的 memory representation。若固定 memory 有效，后续只把 verifier 的 memory-conditioned utility 作为 controller-side 扩展消融。
- 不把 SOMA 直接加入当前 RMBench 搜索空间：它保存 movable-head 扫描得到的跨视角 spatial-semantic map，适用于目标离开视野的任务，属于新的 spatial payload；但当前 Put Back Block 固定相机实验无法公平激活该机制。只有选入明确 out-of-view RMBench 条件并提供可审计位姿/视角输入后，才登记 `spatial_map_store`，不能退化成另一种视觉 token bank。
- 不把 Cortex 整体加入 memory operator catalog：它的主要贡献是 canonical skill vocabulary、planner/executor tractability alignment 与 event-balanced training；其中 subtask history 与现有 key/planner memory 重复，其余属于 planner interface 和数据 recipe。后续可作为 hierarchical planning system 对照，但不新增同义的 `cortex_memory` 开关。
- 不把 LoHo-Manip 整体加入 memory operator catalog：其 `(completed, remaining)` 文本状态可由已登记的 language/progress record 表达；2D visual trace 是经过专门训练的 executor guidance channel，不是历史存储。若后期研究 planner→policy utilization，可在 memory program 之外单独比较 trace/no-trace，但不能用 `loho_memory=true` 重复计数已有 progress memory。
- 不把 Goal2Skill 的 `episodic + working + error` 整体做成一个新 memory 开关：前两项与已有 history/language-state 重叠，error register 应作为 outcome 驱动的 lifecycle payload。其真正新增且可归因的维度是 `postcondition verification → error update → retry/replan`；后续必须拆成独立 operator 与 full lifecycle reference program，不能把 planner、memory 和 recovery 的联合收益记到一个 store 上。
- 不把 Explicit Language Memory 另建成第四套语言 store：recursive rolling summary、completed/pending state 和 failure text 均可由既有 `language_state_update + revisable_progress_record` 表达；只保留它的自动 supervision 与 high/low branch 独立训练 recipe。
- 不复制 BridgeVLA++ 的 temporal memory 总开关：initial anchor、recent buffer 和 learned sub-goal event 已分别由 anchor/sliding/EventVLA-MemCtrl family 覆盖。唯一进入新架构维度的是可按当前 waypoint 重渲染的 canonical 3D spatial anchor。
- 不复制 SERF 的 generic dynamic environment map：该轴已由 AtlasVLA/EchoVLA 保留。SERF 只新增 articulated robot surface 与 environment 的 shared latent state，以及 base/双末端/robot-only/environment-only/global 五组可单独选取的 spatial-relational retriever；当前源码的固定 8-token 顺序必须在 port 时重构为 typed branch，并分别训练，不允许把 inference mask 当成完整消融。
- 不把 MemoryWAM 的 `recent + event anchor + long-range gist` 另建成整体开关：前两项已由 sliding/event/anchor 覆盖，gist compression 应作为 HAMLET-style learned consolidator 的训练变体比较。
- 不把 PRISM 整体登记成新 memory：local-to-global hierarchical compression 与 gated attention 分别落在现有 consolidator 和 adaptive-utilizer 维度；它更适合作为同一 typed program 的强组合基线。
- 不把 WeaveLA 整体登记成新 store：论文的 `sub-goal event → 8-query learned pooling → next-subtask action-expert AdaRMS` 是 writer、consolidator 和 action-side utilizer 的组合。当前新增的 `completed_phase_mean` 只是其中不重复且可独立归因的时序交接 operator：按连续 phase 汇总、排除当前活动段、只向下一 phase 提供最近一个已完成段的 1-token 均值。`completed_phase_handoff / planner_no_key` 与 `key_completed_phase_handoff / key` 分别共享 planner 类型，用于隔离 executor handoff 及其与 key 的组合增益；当前实例使用 RMBench oracle prompt-change，属于诊断性边界下界。该参数无关 reference program 不是完整 WeaveLA；论文级复现仍需 learned 8-token pooling、action-side injection、分阶段联合训练及 learned/oracle trigger 对照。机制审计固化于 `artifacts/2026-08-16-weavela-mechanism-audit.json`（SHA-256 `cfc73705e01736ecdff2d9dcc49d5380d7ad19b3d255a5019b5b25c4b9aa8bfb`）。
- 不把 MIRTH 的完整系统算作 memory module：dual-scale temporal hubs 与现有 dual-rate recurrence 重叠，mutual-information reasoning objective 和 parallel decoder 属于训练/动作头变化。若后期消融，只登记 MI auxiliary objective，不增加 `mirth_memory`。
- 不把 GeneralVLA-2 的 KnowledgeBank 数值作为机器人 memory 证据：其 memory evaluation 实际来自 Terminal-Bench 与 SWE-Bench 软件任务；机器人部分验证的是 3D reconstruction。governance metadata 可借鉴审计字段，但不进入 RMBench module ranking。
- 不把 Mem-World 直接加入 policy memory search：W-VMem 是为 action-conditioned video world model 构建的 surfel-indexed生成上下文；只有项目扩展到 world-model simulator/search 时才作为独立 backend，不能与 π0.5 policy memory 同表。

## 训练边界

- `anchor / sliding / capacity / reset / recent retrieve` 是无需学习的 program operator。
- `novelty_write` 是无需学习的 active-write baseline。它只使用部署可见的当前 contextual latent 与最后保留 latent，不读取 reward、task pointer 或未来信息；每步输出 `WRITE_DECISION` 及距离、阈值和强制写入原因。
- `adjacent_merge_store` 本身无可学习参数，但合并后的 latent 分布不同于 Mem-0 训练时的 raw moment。第一轮复用同一 checkpoint 只能标为 zero-shot compatibility screen；若有正向信号，再用相同更新数做 matched finetune。zero-shot 失败不能直接否定该机制。
- `dhem_event_store` 是 DiM-WAM DHEM 中可独立移植的无学习子算子：容量满时，anchor 与 latest 不参与历史合并；若 incoming 对 latest 的冗余不低于中间历史最冗余相邻对，则丢弃 incoming，否则按累计质量合并历史对并写入 incoming。实现使用论文的语义—时间联合分数与 `tau=N-1`，并在 trace 中记录决策和统计量。
- 当前 `dhem_event_store` 不是完整 DiM-WAM 复现：它复用 π0.5 contextual latent 与 Mem-0 fusion，没有 bank-conditioned summary query、多 bank identity/diversity loss、未来视频预测或 progress auxiliary loss。为适配 harness 的显式有效 mask，冷启动时按事件逐步增长，而不复制论文 tensor 实现中“用首事件填满所有 slot、随后逐个替换”的初始化占位符；满容量后的丢弃/合并规则与公式一致。上述差异都必须与完整模型收益分开报告。
- KEMO 的 motion peak 是延迟确认：在线系统观察短未来窗口后，写入的是先前候选帧，而不是确认时刻的当前帧。`WriteDecision.write_step`、writer lifecycle reset、source/confirmation trace 与 typed `robot_state` 已接入 runtime、OpenPI wrapper 和训练 context generator；跨 episode、未来或 privileged delayed payload 会被拒绝。仓库已有 hash 冻结的 DINOv2 ViT-S/14 encoder 与权重，可复用作 visual dedup。剩余 blocker 是论文只描述“causal local peak + window”而未给精确峰值算法/代码；当前不自行猜测并冒充 KEMO 复现。
- EventVLA 的 event write 使用 action-conditioned hidden state 预测未来 chunk，并由离线 VLM timestamp label 监督；它属于 learned controller。当前不从摘要抽取一个手工阈值版本。
- ChainVLA 的 Motion Tail 是“预测但未执行的 action suffix”，与 observation memory 不重复；但完整路径同时包含 tail token、tail-aligned flow initialization、overlap loss 和执行侧 blending。其纯 Linear Continuation 在 Put Back Block 上仍为 `0%`，不能把后处理 smoothing 当作该模块复现。进入 catalog 的最小单位应是带 checkpoint/recipe 的 learned action-state operator。
- AEM 与 ChainVLA 也不重复：AEM 保存的是**已经执行的动作及其后续视觉效果**，属于 retrospective action-effect representation；Motion Tail 保存的是**已经预测但尚未执行的 action suffix**，属于 prospective action state。AEM 的 `Feature Add / Joint Mamba / Only Memory / Obs Only / full concatenation` 消融表明收益不只是多塞一段历史：Handover Block 分别为 `0.88/0.60/0.44/0.68/0.96`，Place Object Basket 为 `0.52/0.60/0.36/0.44/0.76`。因此进入 harness 时必须把 `executed_action` 作为有来源审计的 causal payload，并携带独立预训练 checkpoint；当前 evaluator 尚未提供这一 typed payload，不提前增加空接口。

## Adjacent-merge 零样本筛选

共享 seed 100000、同一 π0.5 checkpoint 和 30-token budget 下，consolidating 得到 `max_reward=0.15, total_reward=175.05`，sliding 得到 `0.10, 125.75`；两者 full success 均为 0，consolidating 的 mean policy latency 为 `210.67 ms`，sliding 为 `207.62 ms`。该单 seed `+49.30` total-reward 信号只用于触发 matched finetune，不作为方法结论。机器可读结果为 `rmbench_runs/emac_consolidating_vs_sliding_zeroshot_seed100000_20260814.json`。

## Adjacent-merge matched 结论

部署一致的 consolidating context 共 8677 个训练片段，审计全部通过；预算匹配 checkpoint 使用相同 π0.5 base、50 次 optimizer update、effective batch 56 和学习率 `1e-5`。4 个共享 seed 上，sliding 与 consolidating 的平均 max/total reward 分别为 `0.1000/122.350` 与 `0.0875/107.925`，consolidating 的平均 total-reward 差为 `-14.425`，1 胜 3 负，full success 均为 0。离线 matched/empty/mismatched 审计也未通过 utility gate。因此该 store 当前不加入 controller 搜索集合，不再扩大训练预算。

## Novelty-gated write 校准

`novelty_write` 不复制 MemCtrl 的 learned MLLM head，而是为 learned controller 提供更强、更便宜的对照。在 Put Back Block 的 17,512 个同 episode 相邻 latent pairs 上，逐帧 cosine distance 的中位数约为 `8.7e-5`。正式 calibration CLI 从 next-step causal context 重建 50 个 episode 的 17,562 个 source latent；配置 `min_cosine_distance=3e-4`、`max_steps_without_write=30` 后，按“与最后保留项比较”的离线 replay 写入 3,387 次（`19.286%`），其中仅 1 次由 30-step 上限强制触发。该阈值只冻结为当前数据上的 development calibration；正式结论必须比较小型预注册网格，并报告 write rate 与有效时间跨度。机器可读结果当前写至 `/tmp/put_back_block_novelty_calibration.json`，可由 `python -m memory_harness.calibrate_novelty` 确定性重建。

该 operator 改变了 context 分布，因此流程为：先在通过 utility gate 的 always-write checkpoint 上做同 seed zero-shot compatibility screen；只有阶段进度或 success 出现正向信号，才生成部署一致 context 并做预算匹配训练。它不会挤占当前 Put Back Block 1000-update baseline 的优先级。

## DHEM event maintenance 筛选边界

DiM-WAM 在训练匹配的 RMBench 比较中报告平均 full-task success 从 `34.8%` 提升到 `69.8%`，说明“事件选择 + 有界压缩 + learned representation”值得进入 catalog；但该结果来自 LingBot-VA world-action model 的完整 DHEM，不应归因于某一个无参数 store。当前 `fixed_dhem_event.json` 只隔离其 maintenance rule，并保持 30-token budget；先在完成训练的 full-memory checkpoint 上做共享 seed zero-shot screen。若只改变阶段 reward 而不改善 success，则与 novelty/adjacent merge 一样不自动晋级；若出现一致正向信号，再生成该 program 自己的 causal context 做预算匹配 finetune。

在 Put Back Block 现有 50 条 causal source stream 上，`profile_dhem` 重放了 17,562 个 contextual latent。每个 episode 前 30 个事件正常填充；满容量后的 16,062 次决策中，12,052 次丢弃 incoming（`75.03%`），4,010 次合并历史并写入 incoming（`24.97%`）。最终 token 的代表年龄中位数为 `179` environment steps、最大 `362`，累计质量中位数为 `2`、最大 `17`；相同容量的 ring 最老只覆盖约 29 步。因此该规则确实产生长跨度稀疏历史，而非退化成 FIFO。机器可读报告为 `/tmp/put_back_block_dhem_profile.json`；这只证明 store 行为不同，policy utility 仍由已排队的 paired rollout 决定。

## Causal kinematic peak 基线

`fixed_kinematic_event.json` 将 `anchor` 与无 task annotation 的 `causal_kinematic_peak` writer 组合。writer 使用 KEMO 公开的 joint-motion saliency 公式，但把未公开的在线 peak 细节显式定义为 `20` 步 lookback、`20` 步 causal confirmation delay 和 earliest-maximum tie break；因此它是可审计的 inspired baseline，不标为 KEMO 忠实复现。50 条 Put Back Block demonstrations 上，它共选出 `270` 个候选事件，每 episode 为 `4–8` 个，中位数 `5`、均值 `5.4`，没有退化成 dense history 或空 memory。下一层 DINOv2 visual dedup 必须作为独立 writer/filter 接口接入并单独消融；在当前 fixed utility screen 完成前，不为该候选另开训练分支。

## Contextual content + recency 检索基线

`fixed_content_recency.json` 保留每个 episode 最多 500 个 contextual latent，以当前 latent 查询历史，分数为 `cosine_similarity - 1e-5 * frame_gap`，选择 top-30 后恢复时间顺序并填入原有 Mem-0 slots。它改变的是 retrieve 维度，不改变 encode、write 或 utilization；也不冒充 TempoFit 的 layer-wise K/V 实现。

在 50 条 Put Back Block causal source streams（17,562 个 latent）上，机器可读 profiler 对 16,012 个 full-bank queries 比较了 penalty grid。冻结的 `1e-5` 配置平均保留最新 30-step window 的 `85.05%`，即 `14.95%` 的返回项来自窗口外；被选 lag 的中位数为 `16`、P90 为 `38`、最大为 `158`。相比 `1e-4` 的 `98.01%` latest overlap，它没有退化为 FIFO；相比无 recency 的 P90 `201`，又显著抑制 stale retrieval。报告为 `/tmp/put_back_block_content_recency_profile.json`。该参数只用于 zero-shot screen；出现正向信号后才在 development split 上预注册小网格并生成 matched context。

## Semantic + recent quota 检索基线

`fixed_semantic_recent_union.json` 使用同一个 500-item episode bank，固定保留 latest-10，再从当前 contextual latent 的 cosine ranking 中选 20 个不与 recent 重复的历史项。直接实现论文的 `Top20 ∪ Latest10` 时，16,012 个 full-bank queries 平均只返回 `21.52` 项，原因是两分支平均重合 `8.48` 项；正式版本继续向下扫描 semantic ranking 以回填预算，同时把原始重合量记录在每步 trace。

预算匹配版本对全部 full-bank queries 均返回 `30/30` 项，平均 `30.19%` 来自最近 30 步之外；selected lag 中位数 `18`、P90 `197`、最大 `323`。因此它与 sliding 的纯近期窗口和 `content_recency` 的软 age penalty 都形成实质不同的检索分布。机器可读报告为 `/tmp/put_back_block_semantic_recent_union_profile_v2.json`；同 checkpoint 的 sliding 对照已排队，只有 3-episode screen 正向才扩展到 20。

本机单线程 CPU microbenchmark 在 500×2048 bank 上执行 120 次真实 retriever 调用，返回 30 项的 mean/P50/P90/P99 为 `9.05/8.96/9.15/10.97 ms`。这约占现有约 200 ms policy query 的 5%，可进入 screen；正式 rollout 仍以端到端 manifest 的 policy latency 为准，不能用 microbenchmark 代替资源结论。

## Tiered chunk-mean 真实轨迹画像

在 Put Back Block 的 50 条 causal streams、17,612 个 query 上，`tiered_chunk_mean(6/3/8)` 平均只输出 `12.56`、最多 `14` 个 token，但代表的 source history 平均为 `175.68`、最多 `363` 步；`91.20%` 的 query 覆盖了 sliding-30 之外的历史。与同一 source bank 去掉 anchor 后的 sliding history 比较，仅 `1.99%` query 完全相同，flattened cosine 平均为 `0.6683`。因此该模块已证明是不同的压缩长时域 store，而非 sliding 的重复命名；这些数值不证明 policy utility，仍需在 executor floor 建立后做 paired rollout。可复现 CLI 为 `python -m memory_harness.profile_tiered_contexts`，机器可读结果保存在 `artifacts/2026-08-15-tiered-context-profile/summary.json`。

## Temporal multiscale 真实轨迹画像

在相同 Put Back Block source bank 的 16,012 个 full-history query 上，`temporal_multiscale(30,15)` 每次严格返回 30 个 raw tokens，平均 `66.97%` 来自 latest-30 之外，与 sliding 完全相同的 query 为 `0%`。被选 lag 中位数为 `58`、P90 为 `201`、最大为 `362`；每个 query 最老 token 的 lag 中位数为 `191`。

RoboMME 启发的 `uniform_global(30)` 同样固定返回 30 项，但平均 `76.68%` 来自 latest-30 之外，被选 lag 中位数为 `75`。它与 sliding 完全相同的 query 为 `0%`，与 `temporal_multiscale` 完全相同也为 `0%`，两者 selected-set Jaccard 平均仅 `0.1643`。因此三个 fixed retriever 形成 recent-only、uniform episode coverage 和 exponential+uniform multiscale 的明确分解，而非换名重复；policy utility 仍等待 executor floor 后的 shared-seed rollout。可复现 CLI 为 `python -m memory_harness.profile_temporal_multiscale`，机器可读结果保存在 `artifacts/2026-08-15-temporal-multiscale-profile/summary.json`。

显式组合 `recent_global(15+15)` 在同一批 16,012 个 query 上也始终使用 30 项，跨分支 source-step 重复为零，平均 `42.12%` 来自 latest-30 之外；selected lag 中位数 `15.5`、P90 `169`。它与 sliding、uniform-global、temporal-multiscale 的完全相同率均为 `0%`，与后二者的平均 Jaccard 分别为 `0.1578/0.2260`。这证明组合在固定预算下同时保留局部连续性和长期覆盖，不证明 policy utility。

## Boundary-chunk 真实轨迹画像

`boundary_chunk` 是 RoboMME-Interference retrieval 的参数无学习下界，不是其 SigLIP/跨 session 忠实复现。它用相邻 contextual token 的 cosine similarity 切分 episode history，以当前 token 对 chunk 内任一 item 的最大相似度给 chunk 打分，并从获胜 chunk 均匀取至多 30 项。阈值只在 40 条训练 episode 上扫描，按“达到至少 3 个中位 chunk 且 full-history query 不欠预算的最小阈值”冻结为 `0.99935`；选择过程不读取 rollout outcome。

冻结后在未参与选择的 10 条 validation episode、3,207 个 full-history query 上，每次均返回 `30/30` 项，平均 `64.90%` 来自 latest-30 之外，仅 `0.405%` 与 sliding 完全相同；selected lag 中位数 `45`、P90 `121`、最大 `355`。因此它形成 coherent segment retrieval，而不是逐 item content top-k、FIFO 或 uniform-global 的换名。机器可读 calibration/profile 分别为 `configs/calibrations/put_back_boundary_chunk.json` 与 `artifacts/2026-08-15-put-back-boundary-chunk-profile.json`；前者随 candidate suite 冻结，这些结果只证明结构和预算，不证明 policy utility。

## 推荐实现顺序

1. 完成并验证忠实 Mem-0 anchor/sliding port。
2. 在 M(1) 任务检验 anchor/sliding；在 Cover Blocks 检验 key planner。executor floor 建立后，以同一 phase-aware trace 加入 `completed_phase_handoff`，先验证它确实只在 phase transition 后提供上一已完成段，再与 sliding/key 分开归因。若该时序交接有信号，才训练 WeaveLA 的 8-query/action-side版本；key utility 成立后，以同一 planner/executor 边界比较 Mem-0 的 boundary-completion history 与 MemER 的 learned nomination + temporal vote clustering。所有比较先做 planner exactness，再做闭环 success，不能把低层 π0.5 差异计入 memory 收益。
3. `adjacent_merge_store` 已完成比较且无稳定增量；保留实现和负结果，但从 controller 候选集中排除。
4. 用 `novelty_write` 建立 always-write 之外的无训练 active-write 对照；只有正向 zero-shot 信号才做 matched finetune。
5. 对 `dhem_event_store` 做同 checkpoint zero-shot screen；只有正向信号才支付 matched finetune 预算，多 bank learned encoder 暂不启动。
6. 在不改变当前同步路径语义的前提下，增加 typed delayed-write payload 与 joint-state 输入，再实现 KEMO 的 causal motion-peak + visual-dedup writer。
7. Gate 1 后实现 MEM-style dense video window，形成 raw-frame video encoder 与 contextual-latent ring 的 learned representation 对照；当前仓库没有可复用实现，不把它写成待接线的现成功能。
8. `tiered_chunk_mean` 先作为 MemoAct 两级生命周期的无训练 screen；若有信号，再以相同 6/3/8 容量替换为 learned causal chunk compressor，并逐层加入 temporal retrieval 与 gate，避免把四项同时打开。
9. 若固定模块至少一个通过 utility gate，优先移植 TFP 的最小 `LTC belief + AdaLN` 路径，因为它直接基于 π0.5 且官方代码可审计；先分别消融 real/fixed Δt 和 concat/AdaLN，再与 μVLA recurrent tokens、HAMLET causal consolidator比较。
10. 在 learned retriever 分支优先复现 PAM 的 `1-query / 3-range-query / average-pool` 对照；固定同一 context-token encoder、300-frame observation span 和 action→context injection，先验证多跨度 addressability，再决定是否加入 history-image reconstruction objective。
11. NativeMEM 作为第二个 learned representation/utilize 强基线：复用官方 Stage-1 tokenizer → cache → Stage-2 recipe，并与 Mem-0 contextual-latent cross-attention 做训练预算和 token 预算匹配。
12. `verified_success_ring` 已先建立 ordered persistent-deployment 的 transactional lifecycle lower bound；它只提交成功 episode，失败轨迹不可见。Gate 1 后再把 OptimusVLA GPM 作为首个跨 episode action-prior family：固定 demonstration bank coverage，比较 Gaussian noise、随机/错误 trajectory prior 与 semantic top-k prior；随后在同一 action payload/utilizer 上加入 Retrieve-then-Steer 的 progress-peak truncation、DTW consistency filter 与 confidence-adaptive guidance，并比较 offline demonstration bank、online verified bank、unverified bank 和 direct replay。LCM 不重复登记。
13. fixed utility gate 后，比较最小 recurrent state 与 ChainVLA-style Motion Tail；两者分别代表 observation-derived retrospective state 与 prediction-derived prospective state，必须 ordered/matched training。
14. 在 observation-only recurrence 证明有用后，先利用现有部署可见 14D robot-state stream 建立 VQ-Memory 的 `none/raw/VQ256/clustered-VQ4` representation factorial；只有本地 tokenizer contract 完整或官方 release 可审计时才训练。随后把 AEM 接成第一种 executed-action representation：扩展 causal action payload 与数据审计，独立预训练 encoder，在相同 downstream 更新预算下比较 proprio-only、action-only、feature-add 与 vision-action joint encoder；不与 Motion Tail 同时加入。
15. LaMem-VLA 的官方实现可审计后，复用现有 dual vault、adjacent merge 与 reset，只实现 action-hidden writer、multimodal query、dual top-K、query-conditioned condenser 和 source-tagged native-prefix weave；先重放官方 factorial，再做 π0.5 的 `none/short/long/dual` 与 `policy-side/raw/native-prefix`。30.7 GB 权重包没有配套源码、配置或 loader，在代码发布前不根据论文公式猜实现，也不单独重跑重叠的 adjacent merge。
16. 最小 μVLA recurrence 若通过 matched gate，再加入 ReMem-VLA 的第二个 chunk-rate EMA state；先隔离单层 recurrence，再比较 dual-rate，Past Observation Prediction 作为另一个独立训练目标，不与 recurrence 同时加入。
17. controller 能稳定选择已有模块后，再开放 EventVLA foresight head、language-state update、DHEM multi-bank 和 Chameleon-style control-indexed/prospective operator evolution。
18. 将 HyMeS 作为最近且最接近的强参照：先等待/审计官方实现；若实现可用，分离复现 symbolic state、PACE verifier 与 constraint steering，禁止将三者整体效果归因于 memory architecture。E-MAC 的 Agent 评测必须额外证明跨任务 typed program 的迁移和相对 random/evolutionary search 的预算优势。
19. executor floor 建立后，在同一 checkpoint、共享 seed 和严格 30 raw-token 预算下同时比较 `sliding / uniform_global / recent_global / temporal_multiscale / boundary_chunk / content_recency / semantic_recent_union`；只有 positive signal 才为对应 retrieve 生成 matched context training。CycleManip 的 dense joint-state encoder 与 progress objective 留到 Gate 1 顺序训练；TempoFit 官方仓库解除 Coming Soon 后，再分层消融 K/V store、FGTB 与 residual utilizer。
20. Gate 1 后补做 MemoryVLA 的完整 PCMB learned 对照，先固定相同有效 token/训练预算分别比较单 cognitive stream、单 perceptual stream和 dual stream，再拆 timestep encoding、cross-attention retrieval 与 gate；现有 adjacent-merge 负结果只作为 store 消融。
21. 只有 flat learned memory 已稳定有效且需要更大容量/跨组合泛化时，才进入 ECHO-style semantic tree；在官方代码缺失期间只冻结候选接口，不提前增加未使用的 tree abstraction。
22. 当实验扩展到具备 RGB-D/位姿输入、跨 episode object re-identification 和 skill reuse 的条件后，再加入 Analytic Concept-Centric Memory 的 structured payload family；先比较 object+scene，再逐层加入 transition、skill 与 outcome verification，避免把 perception tool、planner 和 memory 的系统收益混为一体。
23. RMBench 的固定 memory utility 成立后，把 RoboMME 作为首个 locked transfer benchmark：先直接复用官方 π0.5 baseline 与 FrameSamp+Modulator checkpoint 验证 evaluator，再在相同 16-task split 上比较 harness 候选。Agent 搜索必须在部分任务开发、其余任务锁定的条件下报告 temporal/spatial/object/procedural 四类迁移，不能把同一任务上的 architecture tuning 当作通用发现。
24. controller 在 locked transfer 上稳定后，再开放 VLA-Pro-style parameter memory：先定义 task-LoRA typed payload 与原子 load/unload 生命周期，按 `base / oracle adapter / wrong adapter / learned top-k / factor interpolation / dense-delta interpolation` 分层消融；训练任务与 held-out 任务严格分离，并把 adapter 总参数、外部 state-extractor 调用和切换延迟计入搜索预算。
