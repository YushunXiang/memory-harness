# E-MAC RMBench 3-Episode Development Pilot

日期：2026-08-14

## 结论

> 历史记录：此结论仅适用于已废止的 shared-adapter 分支，已被后续 Mem-0 port 取代；整个 E-MAC 项目当前为 ACTIVE / Yellow。

> **历史记录，已被 v4 Mem-0 port 取代。** shared-adapter pilot 已停止；当前项目为 **ACTIVE / reproduction in progress**。

当时决策为 **STOP shared-adapter branch**：保留 modular memory harness，暂不训练 controller，也不进入主动写入或跨 episode architecture evolution。

原因是 oracle phase prompt 只产生了弱 capability signal，而同一 context-adapter checkpoint 上没有任何 fixed memory 在三个配对 seeds 上稳定优于 none。所有条件完整成功率均为 0/3；anchor 与 anchor+sliding 虽在一个 seed 上推进更深，却在另一个 seed 上把最高奖励从 0.30 降到 0.05，整体是负收益。

## 冻结协议

- Task：RMBench `cover_blocks / demo_clean`
- Executor：`mplib_RRT`（当前节点缺 cuRobo/pytorch3d）
- 每个条件：3 episodes × 1500 steps × action chunk 10
- Simulator seeds：100000、100001、100002
- Policy seeds：120000、120001、120002
- Layout fingerprints：`[1,2,0]`、`[2,1,0]`、`[0,2,1]`
- `policy_adapt_to_pi=false`
- Fixed comparison checkpoint：`pi05_aloha_pen_uncap_context_adapter/.../100`
- Oracle capability checkpoint：base π0.5 `.../9999`

所有有效运行均为 0 evaluator errors。clean 和五个 fixed runs 通过 manifest；oracle 的 phase trace 每 25 steps 记录一次。

## 结果

| Condition | max reward by paired seed | mean max reward | success | mean inference | max memory tokens |
|---|---:|---:|---:|---:|---:|
| base clean | 0.05 / 0.05 / 0.10 | 0.067 | 0/3 | — | 0 |
| oracle phase prompt | 0.10 / 0.05 / 0.10 | 0.083 | 0/3 | — | 0 |
| fixed none | 0.05 / 0.30 / 0.10 | 0.150 | 0/3 | 105.7 ms | 0 |
| anchor | 0.10 / 0.05 / 0.10 | 0.083 | 0/3 | 212.4 ms | 4 |
| sliding | 0.05 / 0.05 / 0.10 | 0.067 | 0/3 | 139.8 ms | 8 |
| anchor + sliding | 0.10 / 0.05 / 0.10 | 0.083 | 0/3 | 207.6 ms | 8 |
| key skeleton | 0.05 / 0.05 / 0.10 | 0.067 | 0/3 | 146.5 ms | 4 |

Oracle 的最大 phase pointer 为 `2 / 1 / 2`，对比 base clean 仅在 seed 100000 多推进一阶段，说明 executor/policy 不是完全没有阶段推进能力，但证据不足以支持扩大 memory search。

相对 fixed none，四个非空 memory 的 paired max-reward delta 分别为：

- anchor：`+0.05 / -0.25 / 0.00`
- sliding：`0.00 / -0.25 / 0.00`
- anchor + sliding：`+0.05 / -0.25 / 0.00`
- key skeleton：`0.00 / -0.25 / 0.00`

这表明当前主要现象是 memory interference，不是稳定 memory advantage。非空 memory 还带来约 32%–101% 的平均 inference latency 增量。

## Key 条件解释

本轮 key audit 中，3 次 WRITE 和 450 次 RETRIEVE 的 phase 全为空字符串。它实际退化为“每 episode 固定一个早期 memory item”，只能作为接口/负面对照，不能作为有效 M(n) key/subtask baseline。后续必须先加入仅依赖可部署观测的视觉/语言 phase estimator。

## 协议纠错

首次运行错误地继承了 config 默认的 `adapt_to_pi=true`，与 base 和 context-adapter 训练时的 `--data.no-adapt-to-pi` 不一致，因此全部判为无效并改名为：

- `emac_clean_none_dev3_chunk10_mplib_20260814_v2_invalid_adapt_true`
- `emac_oracle_phase_dev3_chunk10_mplib_20260814_invalid_adapt_true`
- `emac_fixed_none_dev3_chunk10_mplib_20260814_invalid_adapt_true_interrupted`

runner 现已强制 `POLICY_ADAPT_TO_PI=0`，clean/fixed validator 也会拒绝其他值。

## Gate 决策

- Oracle gate：弱通过。存在一组配对阶段推进，但无完整成功改善。
- Fixed-memory gate：未通过。没有模块稳定优于 fixed none，且四个非空条件都破坏了 seed 100001 的深阶段能力。
- Controller gate：不启动。当前训练 controller 只会学习在多个未验证模块之间选择。
- Content intervention：暂不启动。proposal 要求先有至少一个 fixed 模块通过验证；当前不满足。

下一步应先定位 utilization/interference：用保存的相同 observations 做 none-vs-memory action parity，检查 memory token scaling/mask 与 cross-attention 强度；同时实现非 privileged phase estimator。只有修正后某个 fixed 模块在扩展 seeds 上保住 fixed-none 的 0.30 阶段能力并产生一致正 delta，才恢复 remove/shuffle/stale/oracle 内容消融和 controller 训练。
